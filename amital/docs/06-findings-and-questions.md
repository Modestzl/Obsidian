## Что пока нельзя утверждать

- Нельзя назвать активную тему, полный список включённых модулей и реальные значения лимитов без выбранных настроек из БД.
- Нельзя назвать конкретную стороннюю сборку или точный объём отличий от OpenCart 1.5.6.4 без сравнения с эталоном.
- Нельзя утверждать, что все изменения XML применяются, а сохранённый кеш соответствует текущим XML/исходникам.
- Нельзя назвать версию PHP, настройки Apache/nginx, `DirectoryIndex`, расписание cron, действующую конфигурацию/версию Sphinx или Memcache.
- Не найден и не прослежен полный механизм поступления товаров, цен и остатков из внешней учётной системы. `1c/index.php` сам по себе этого не подтверждает.
- Не проверены все варианты checkout, права действий кабинета, платёжные уведомления, механизм резервирования/списания остатков и последовательность скидок.
- Нельзя считать похожие файлы (`product01.php`, `00checkout.php`, `ami3_backup` и др.) неиспользуемыми только по имени. Необходимо проследить динамические вызовы и серверные задания.

## Минимальные внешние сведения — когда понадобятся

Сейчас файлы позволяют продолжать анализ; полный дамп БД не требуется. Перед запросом данных согласовать конкретный минимальный набор:

- Для темы: только `store_id`, `key`, `value` строк `config_template` и при необходимости `config_store_id`/макетов.
- Для расширений: записи `oc_extension`, структура макетов и только нужные статусы/настройки размещения, без реквизитов сервисов.
- Для остатков: структура `oc_product`, `oc_product_to_shops`, `oc_category_path`, `oc_category_description`, `oc_stock_status`; несколько обезличенных товаров с полями остатка/цены/статуса и дерево узла `239`.
- Для лимитов: выбранные несекретные значения `min_order_price`, `config_stock_checkout`, `config_stock_warning`, `low_order_fee_*` и относящихся к исследуемой доставке порогов.
- Для сервера: версия PHP и необходимые расширения, очищенный от секретов список команд расписания, соответствующие фрагменты конфигурации веб-сервера и Sphinx. Не публиковать `phpinfo()` ради этого.

Таблицы клиентов, адресов, заказов, рассылок и значения паролей/токенов для первичной инвентаризации не нужны. Содержимое `oc_setting` целиком запрашивать нельзя: там могут быть секреты интеграций.
